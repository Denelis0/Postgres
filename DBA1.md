### Этап 1: Зачистка «ручного» кластера
*Цель: Остановить и удалить тот кластер, который вы создали через `initdb` и запускали через `pg_ctl`.*

1.  **Останавливаем процесс:**
    *(Используйте тот путь, где вы создавали этот кластер. Предположим, это `/var/lib/postgres/16/prod`)*.
    ```bash
    sudo -u postgres /usr/lib/postgres/16/bin/pg_ctl -D /var/lib/postgres/16/prod stop
    ```
    *Если пишет "PID file not found" или ошибка — найдите процесс через `ps aux | grep postgres` и убейте его через `kill`.*

2.  **Удаляем папку:**
    ```bash
    sudo rm -rf /var/lib/postgres/16/prod
    ```

---

### Этап 2: Переименование старого кластера
*Цель: Дать старому кластеру (main) имя `test`, чтобы освободить имя `prod` для нового.*

1.  **Переименовываем:**
    Команда `pg_renamecluster` переименует службу, папки конфигов и ссылки. Порт останется прежним (5432).
    ```bash
    # Синтаксис: <версия> <старое_имя> <новое_имя>
    sudo pg_renamecluster 16 main test
    ```

2.  **Проверяем:**
    ```bash
    pg_lsclusters
    ```
    *Должно быть: `16 test 5432 online ...`*

---

### Этап 3: Создание нового «правильного» кластера
*Цель: Создать пустую заготовку для Prod-базы с системной службой.*

1.  **Создаем кластер `prod` на порту 5433:**
    ```bash
    sudo pg_createcluster 16 prod --port 5433
    ```
    *Система сама создаст папки в `/var/lib/postgresql/16/prod` и конфиги в `/etc/postgresql/16/prod`.*

2.  **Останавливаем его (чтобы залить бэкап):**
    ```bash
    sudo systemctl stop postgresql@16-prod
    ```

3.  **Очищаем папку данных (она должна быть пустой для бэкапа):**
    ```bash
    sudo rm -rf /var/lib/postgresql/16/prod/*
    ```

---

### Этап 4: Клонирование (Basebackup)
*Цель: Скопировать данные из старого (`test`, порт 5432) в новый (`prod`, папка для 5433).*

1.  **Запускаем копирование:**
    ```bash
    sudo -u postgres /usr/lib/postgres/16/bin/pg_basebackup \
      -h localhost \
      -p 5432 \
      -D /var/lib/postgresql/16/prod \
      -Fp -Xs -P -j 4
    ```

2.  **?? Исправление конфигов (Самый важный шаг):**
    Вместе с бэкапом скопировался файл `postgresql.conf` от старого кластера, где прописан порт 5432. Нам нужно убедиться, что новый кластер встанет на порт 5433.

    *В Debian/Ubuntu настройки приоритетнее брать из `/etc/...`, но для надежности лучше поправить и внутри.*
    
    *   **Открываем конфиг, который приехал с бэкапом:**
        ```bash
        sudo nano /var/lib/postgresql/16/prod/postgresql.conf
        ```
    *   **Меняем порт:** `port = 5433`
    *   **Удаляем лишнее:** Если есть файл `postmaster.pid` в этой же папке — удалите его:
        ```bash
        sudo rm -f /var/lib/postgresql/16/prod/postmaster.pid
        ```

3.  **Запускаем новый кластер:**
    ```bash
    sudo systemctl start postgresql@16-prod
    ```

---

### Итог
После выполнения этих шагов будет:
1.  **Кластер `test`** (бывший main) на порту **5432**.
2.  **Кластер `prod`** (новый клон) на порту **5433**.
3.  Оба управляются через `systemctl`.
