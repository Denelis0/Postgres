# Тема 1: Установка и управление сервером PostgreSQL 16


## 1. Основные понятия

\*   \*\*Кластер баз данных (Database Cluster):\*\* Совокупность файлов, хранящихся на диске в каталоге данных (`PGDATA`). Это физические данные.

\*   \*\*Экземпляр сервера (Server Instance):\*\* Работающая программа (набор процессов) + выделенная оперативная память, управляющая доступом к кластеру.



## 2. Инициализация и переменные окружения



### Переменные окружения

\*   `PGDATA`: Путь к каталогу, где лежит кластер.

&nbsp;   \*   Пример: `export PGDATA=/home/student/pgsql16/data`

\*   `PATH`: Путь к исполняемым файлам (бинарникам) Postgres, чтобы не вводить полный путь каждый раз.

&nbsp;   \*   Пример: `export PATH=/usr/lib/postgresql/16/bin:$PATH`



> \*\*Важно:\*\* Чтобы переменные сохранялись после перезагрузки или закрытия терминала, их нужно добавить в файл конфигурации оболочки (например, `~/.bashrc` или `~/.bash\_profile`).



### Утилита initdb

Используется для создания (инициализации) нового кластера.

```bash

initdb -U postgres -k -D /home/student/pgsql16/data

```

\*   `-U postgres`: Указывает суперпользователя базы данных.

\*   `-k` (или `--data-checksums`): Включает подсчет контрольных сумм страниц данных.

\*   `-D`: Указывает путь к каталогу данных (если не задана `PGDATA`).



### Просмотр конфигурации

\*   `pg\_config`: Показывает параметры \*\*сборки\*\* PostgreSQL (пути к файлам, версии библиотек). \*\*Не\*\* показывает настройки текущего кластера.

\*   `SHOW ALL;` (внутри SQL) или просмотр `postgresql.conf`: Используется для просмотра настроек работающего кластера.



## 3. Права доступа и файловая система (Linux)

PostgreSQL разделяет исполняемый код и данные пользователя по соображениям безопасности:



1\.  \*\*Бинарные файлы\*\* (`/usr/lib/postgresql/16/...`):

&nbsp;   \*   \*\*Владелец:\*\* `root`.

&nbsp;   \*   \*\*Зачем:\*\* Защита от подмены кода вредоносными программами. Только администратор системы может обновлять ПО.

2\.  \*\*Данные\*\* (`/var/lib/postgresql/16/main` или `~/pgsql16/data`):

&nbsp;   \*   \*\*Владелец:\*\* `postgres`.

&nbsp;   \*   \*\*Зачем:\*\* Процесс СУБД должен иметь полные права на чтение и запись в эту папку. Если владельцем будет `root`, база не запустится (`Permission denied`).



## 4. Управление сервером: pg\_ctl vs pg\_ctlcluster



| Утилита | Описание | Когда использовать |

| :--- | :--- | :--- |

| \*\*pg\_ctl\*\* | Родная кроссплатформенная утилита Postgres. Работает напрямую с папкой данных. | При ручной установке (из исходников, архивов), в учебных целях, на Windows. |

| \*\*pg\_ctlcluster\*\* | Обертка (wrapper) для Debian/Ubuntu. Интегрирована с `systemd` и знает структуру конфигов Debian (`/etc/postgresql/...`). | На production серверах с ОС Ubuntu/Debian (в т.ч. для 1С). |



## 5. FAQ (Важные нюансы для Production/1С)



\*\*В: Стоит ли включать контрольные суммы (`-k`) для базы 1С (HighLoad, 1000+ пользователей)?\*\*

\*\*О: Обязательно.\*\*

\*   Контрольные суммы позволяют выявить физическое повреждение данных (битые сектора диска) в момент чтения.

\*   Влияние на производительность (CPU) в современных системах ничтожно мало.

\*   Включить их \*после\* создания базы сложно (требует остановки базы и прогона утилиты по всему объему данных), поэтому лучше делать это при `initdb`.



\*\*В: Как проверить, включены ли контрольные суммы?\*\*

\*\*О:\*\* SQL-запросом: `SHOW data\_checksums;`

\### Полезные команды



```bash

\# Инициализация кластера с чексуммами

/usr/lib/postgresql/16/bin/initdb -D /var/lib/postgresql/16/main -k



\# Запуск сервера (через pg\_ctl)

pg\_ctl -D /var/lib/postgresql/16/main start



\# Запуск сервера (Debian way)

pg\_ctlcluster 16 main start

\# или

systemctl start postgresql@16-main

```
