# Тема 3: Конфигурирование сервера PostgreSQL

## 1. Конфигурационные файлы
PostgreSQL управляется через текстовые файлы. Основные из них:

1.  **`postgresql.conf`**: Основной файл настроек.
    *   *Расположение:* Обычно в `PGDATA` или в `/etc/postgresql/16/main/` (Debian/Ubuntu).
    *   *Как найти:* SQL-команда `SHOW config_file;`.
2.  **`postgresql.auto.conf`**: Файл для автоматических изменений.
    *   *Расположение:* Всегда в `PGDATA`.
    *   *Особенность:* Имеет приоритет над основным файлом (читается последним).
    *   *Редактирование:* Руками трогать не рекомендуется, управляется командой `ALTER SYSTEM`.

## 2. Управление настройками

### Изменение параметров
1.  **Ручное:** Редактирование `postgresql.conf` -> Перечитывание (`reload`) или Перезапуск (`restart`).
2.  **SQL-команда (глобально):**
    ```sql
    -- Записывает изменение в postgresql.auto.conf
    ALTER SYSTEM SET work_mem = '16MB';
    -- Сброс настройки (удаление из auto.conf)
    ALTER SYSTEM RESET work_mem;
    ```
    *Важно: После `ALTER SYSTEM` все равно нужно сделать reload или restart.*
3.  **SQL-команда (локально для сессии):**
    ```sql
    -- Действует только до конца текущего соединения
    SET work_mem = '64MB';
    ```

### Применение изменений
*   **Reload (Перечитывание):** Применяет параметры, не требующие рестарта (context = sighup/user). Не прерывает работу пользователей.
    *   SQL: `SELECT pg_reload_conf();`
    *   Shell: `pg_ctl reload`
*   **Restart (Перезапуск):** Нужен для фундаментальных параметров (память, порты, воркеры). Прерывает соединения.

## 3. Системные представления (Views)

### `pg_settings` — Текущее состояние (Память)
Показывает параметры, действующие **прямо сейчас**.
*   **`setting`**: Текущее значение.
*   **`pending_restart`**: `t` (true), если параметр изменен в файле, но ждет рестарта сервера.
*   **`context`**: Условие изменения параметра:
    *   `postmaster`: Требует **Restart** (перезапуск процесса). Пример: `shared_buffers`, `max_connections`.
    *   `sighup`: Требует **Reload** (HUP сигнал). Пример: `log_min_duration_statement`.
    *   `user`/`superuser`: Можно менять на лету (`SET`) без reload. Пример: `work_mem`.

### `pg_file_settings` — Содержимое файлов (Диск)
Показывает "сырые" данные из конфигурационных файлов.
*   Позволяет найти ошибки (`error` не пустой) или дублирующиеся строки.
*   Поле `applied`: Показывает, применилась ли настройка (если `false`, возможно, она перекрыта ниже или ошибочна).

## 4. FAQ и полезные запросы

**В: Как узнать максимальное число соединений?**
```sql
SHOW max_connections;
```
*Для изменения этого параметра требуется рестарт сервера.*

**В: Как проверить, какие параметры требуют рестарта?**
```sql
SELECT name, setting 
FROM pg_settings 
WHERE pending_restart = true;
```

**В: Как посмотреть все параметры с описанием?**
```sql
SELECT name, setting, unit, short_desc 
FROM pg_settings;
```
