
## ## 1. Сетевые настройки (TCP/IP)
*   **Техническая суть**: Этот параметр определяет, к каким сетевым картам (интерфейсам) «привяжется» процесс PostgreSQL при старте. Если адреса нет в этом списке, ядро ОС будет просто отбрасывать пакеты, приходящие на порт 5432 для этого IP.
*   **Варианты конфигурации**:
    *   `'localhost'`: Позволяет подключаться только с того же сервера. Безопасно, так как база физически не видит внешнюю сеть.
    *   `'*'`: Сервер слушает все доступные интерфейсы (Ethernet, Wi-Fi, VPN, Loopback). Самый гибкий, но опасный вариант — база «светится» везде.
    *   **Список IP**: Например, `'192.168.1.50, localhost'`. Позволяет базе отвечать только по внутренней (доверенной) сети и локально.
*   **Важные нюансы**:
    *   **IPv6**: Запись `::` означает «слушать все IPv6 адреса». Запись `0.0.0.0` — все IPv4.
    *   **Приоритет безопасности**: Это первый эшелон защиты. Если здесь не указан публичный IP, то даже с правильным паролем и настройками в `pg_hba.conf` никто из интернета не сможет даже «достучаться» до порта.
    *   **Применение**: Требуется полный `restart`, так как сокеты TCP создаются операционной системой в момент запуска процесса.

## ## 2. Лимиты и резервирование соединений
*   **`max_connections`**: Максимальное количество одновременных подключений.
    *   Каждое соединение создает процесс в ОС и потребляет RAM (~10-20 МБ + `work_mem`).
    *   Не рекомендуется завышать без пулеров (PgBouncer), так как это снижает производительность CPU.
    *   **Применение:** Требуется `restart`.
*   **`superuser_reserved_connections`**: Количество слотов, зарезервированных для суперпользователей (`postgres`).
    *   Позволяет админу зайти в базу, даже если обычные пользователи заняли все доступные лимиты.
    *   **Применение:** Требуется `restart`.
*   **`reserved_connections`** (PostgreSQL 16+): Резерв для ролей с правом `pg_use_reserved_connections`.
    *   Используется для бесперебойной работы систем мониторинга или бэкапов.
    *   **Применение:** Требуется `restart`.

## ## 3. Локальные сокеты (Unix Sockets)
*   **Техническая суть**: Задает пути к каталогам, где PostgreSQL создаст специальный файл — **Unix Domain Socket**. Это не обычный файл, а «труба» в памяти ядра ОС для сверхбыстрой передачи данных между процессами.
*   **Почему это важно**:
    *   **Производительность**: Общение через сокет на 10-20% быстрее, чем через сетевой адрес `127.0.0.1`. Данные не упаковываются в TCP-пакеты и не проходят проверки контрольных сумм.
    *   **Безопасность**: Доступ к сокету можно ограничить на уровне прав файловой системы Linux (см. `unix_socket_permissions`).
*   **Механика работы**:
    *   При старте в указанной папке появляется файл с именем вида `.s.PGSQL.5432`.
    *   Если папок несколько (например, `'/var/run/postgresql, /tmp'`), сокеты будут созданы в каждой. Это полезно для совместимости с разными клиентами.
    *   Утилита `psql` по умолчанию сначала ищет сокет в стандартных путях, и только если не находит — пытается идти через TCP/IP.
*   **Особенности Enterprise/Pro версий**:
    *   В системах высокой доступности (например, с утилитой `bihactl`) этот параметр часто управляется автоматически. Ручное изменение может «сломать» логику кластера.
*   **Применение**: Требуется `restart`.
*   **`unix_socket_group`**: Задает группу ОС, которая будет владеть файлом сокета.
    *   Позволяет пользователям из этой группы (например, `www-data`) подключаться к сокету.
    *   **Применение:** Требуется `restart`.
*   **`unix_socket_permissions`**: Устанавливает права доступа на файл сокета в формате Unix (права доступа).
    *   `0777`: Разрешить подключаться всем пользователям сервера (по умолчанию).
    *   `0700`: Только владелец процесса postgres может использовать сокет.
    *   **Применение:** Требуется `restart`.

## ## 4. Сравнение: Сеть vs Сокет
*   **Когда использовать TCP/IP (`listen_addresses`)**:
    *   Приложение и база на разных серверах.
    *   Использование Windows (там сокеты реализованы иначе).
*   **Когда использовать Сокет (`unix_socket_directories`)**:
    *   Приложение (PHP, Python, Java) живет на том же сервере, что и база.
    *   Запуск локальных бэкапов (`pg_dump`) или скриптов обслуживания.
    *   Нужна максимальная пропускная способность при передаче больших объемов данных внутри сервера.
