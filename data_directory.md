# Parameter: `data_directory`

## Описание
Указывает абсолютный путь к каталогу файловой системы, где PostgreSQL хранит файлы баз данных, глобальные данные кластера и (по умолчанию) журналы предзаписи (WAL) и конфигурационные файлы.

## Основные характеристики
| Характеристика | Описание |
| :--- | :--- |
| **Тип** | String (путь к директории) |
| **Рестарт** | **Требуется** (изменение пути невозможно на лету) |
| **Значение по умолчанию** | Зависит от ОС (обычно `/var/lib/postgresql/...`) |
| **Контекст** | Postmaster (задается при старте процесса) |

## Приоритет установки (от высшего к низшему)
PostgreSQL определяет путь к данным в следующем порядке:
1.  **Флаг запуска `-D`** (или `--pgdata`).
2.  **Переменная окружения `PGDATA`**.
3.  **Параметр `data_directory`** внутри `postgresql.conf` (игнорируется, если задан п.1 или п.2).

### ❓ Где хранится информация, если используется флаг `-D`?
Если сервер запускается с флагом `-D` (что является стандартом для Linux-дистрибутивов), путь **не перезаписывается** внутри конфигурационных файлов самого PostgreSQL.
Эта настройка хранится на уровне **менеджера службы** операционной системы:
*   **Systemd:** В Unit-файле (обычно строка `Environment=PGDATA=...` или в команде `ExecStart`). Может быть по пути `/etc/default/postgrespro-ent-17` (PGDATA=/var/lib/pgpro/ent-17/prod_cluster).
*   **Environment files:** В файлах типа `/etc/postgresql/...` (Debian/Ubuntu) или `/etc/sysconfig/pgsql/` (RHEL), откуда скрипт запуска считывает переменную. Также может быть по пути `/etc/systemd/system/postgrespro-ent-17-test.service` (Environment=PGDATA=/var/lib/pgpro/ent-17/test_cluster)
*   **Docker:** В переменной `PGDATA` внутри Dockerfile или docker-compose.yml.

## Важно
*   **Разделение дисков:** Критично для производительности. Директорию данных следует размещать на отдельном физическом носителе (SSD), чтобы отделить I/O базы данных от системных операций ОС и свопинга (перенос некоторой инфы с ОЗУ на жесткий диск).
*   **Права доступа:** Директория должна принадлежать пользователю `postgres`. Права доступа строго `0700` (только владелец читает/пишет) или `0750` (группа может читать). При более широких правах сервер откажется запускаться в целях безопасности.

## Перенос данных (смена директории)
Алгоритм действий для переноса `data_directory`:
1.  Остановить сервер PostgreSQL.
2.  Скопировать данные с сохранением прав и владельца:
    `rsync -av /var/lib/postgresql/data /new/disk/path`
3.  Изменить путь в конфигурации (в `postgresql.conf` или в unit-файле systemd, в зависимости от того, как запускается служба).
4.  Запустить сервер.

## Пример настройки и проверка

**В файле `postgresql.conf`:**
```ini
data_directory = '/mnt/nvme_storage/pgsql/data'
```

**Проверка текущего пути (SQL):**
```sql
SHOW data_directory;
```
